# LinkedIn AI Post Automation

Publish quality LinkedIn posts on a schedule — generated by **Gemini AI** from your own notes, checked by a **self-review validator**, and published through the official **LinkedIn API** with a fail-safe, dry-run-first pipeline.

Built for developers who want to share their learning journey consistently without writing every post by hand.

> **100% Free** — this entire workflow costs nothing: GitHub Actions free
> automation minutes, Gemini AI free tier, and the LinkedIn API. No paid
> plans, no credit card, no hidden fees.

---

## Features

- **Scheduled publishing** — GitHub Actions runs your workflow on a cron schedule (default: Monday & Wednesday).
- **Knowledge-driven** — feeds on your `today_notes`, syllabus, previous posts, and writing rules (each optional).
- **Varied output** — random length tiers, opening styles, paragraph layouts, and tones so posts don't all look alike.
- **Self-review** — word/emoji/hashtag counts, markdown checks, hype-word detection, repeated-opening detection, and a similarity check against your archive.
- **Rewrite loop** — up to 3 automatic rewrites; if it still fails, the post is **rejected and never published**.
- **Dry-run mode** — generate and inspect a post locally without publishing anything. The recommended first test.
- **Fail-safe** — missing keys stop with clear errors; `today_notes.txt` is only cleared after a **successful** publish.
- **No secrets in the repo** — everything is configured through environment variables / GitHub Secrets.

## How It Works

```
GitHub Actions (cron)
        ↓
Node.js Automation
        ↓
Knowledge Sources (notes → syllabus → archive → rules)
        ↓
Gemini (generates post with random style)
        ↓
Quality Validation (self-review)
        ↓
Rewrite if Needed (max 3 attempts)
        ↓
LinkedIn API (publish)
        ↓
Archive (track history, avoid repetition)
```

## Configuration

Create your local `.env` from the template:

```bash
cp .env.example .env
```

Then edit `.env` and fill in at least `GEMINI_API_KEY`:

```env
GEMINI_API_KEY=your_gemini_api_key_here
LINKEDIN_ACCESS_TOKEN=your_linkedin_access_token_here
```

> `.env` is gitignored. Never commit it.

### Environment variables

| Variable | Required | Purpose |
|----------|----------|---------|
| `GEMINI_API_KEY` | ✅ (generation) | Google AI Studio API key |
| `LINKEDIN_ACCESS_TOKEN` | ✅ (publishing) | LinkedIn OAuth token with `w_member_social` scope |
| `LINKEDIN_CLIENT_ID` | auth only | LinkedIn app ID, used by `npm run auth` |
| `LINKEDIN_CLIENT_SECRET` | auth only | LinkedIn app secret, used by `npm run auth` |
| `LINKEDIN_REDIRECT_URI` | auth only | Must match your app's registered redirect URL |
| `POST_TIMEZONE` | optional | Timezone for day checks (default `UTC`) |
| `MONDAY_TOPIC` | optional | Overrides Monday topic |
| `WEDNESDAY_TOPIC` | optional | Overrides Wednesday topic |
| `SCHEDULE_DAYS` | optional | Comma list, e.g. `monday,thursday` |
| `REQUIRED_HASHTAGS` | optional | Comma list enforced by the validator |

Most preferences (topics, limits, hashtags) can also live in
`config/settings.json` — copy `config/settings.example.json` to
`config/settings.json` and edit. Environment variables always win.

## Knowledge Files

Copy the example files and replace them with your own content. **All of them
are optional** — missing files are handled gracefully.

| File | Priority | Purpose |
|------|----------|---------|
| `config/today_notes.txt` | 1 | Today's specific knowledge — the main ingredient for the next post |
| `config/syllabus.txt` | 2 | Broader subject/curriculum context, used when today's notes are empty |
| `archive/*.md` | 3 | Your previous posts — used to avoid repeating topics and openings |
| `config/rules.txt` | 4 | Your writing style and quality rules, injected into every prompt |
| `config/identity.txt` | — | One paragraph describing who the posts are written as |

```bash
cp config/today_notes.example.txt config/today_notes.txt
cp config/syllabus.example.txt config/syllabus.txt
cp config/rules.example.txt config/rules.txt
cp config/identity.example.txt config/identity.txt
```

## LinkedIn Authentication

This project uses the **official LinkedIn OAuth 2.0 Authorization Code flow** —
no MCP servers, no third-party tools.

### 1. Create a LinkedIn Developer App

1. Go to https://www.linkedin.com/developers/apps and create an app.
2. Request the **Share on LinkedIn** product (`w_member_social` scope).
3. Under **Auth**, add an authorized redirect URL, e.g.
   `http://127.0.0.1:8585/callback`.
4. Note your **Client ID** and **Client Secret**.

### 2. Generate an access token

```bash
npm run auth
```

The script prints a URL. Open it, log in, approve the requested scope, and
paste back the redirect URL you are sent to (it contains `?code=...`). The
script exchanges the code for an access token and prints it.

### 3. Store the token

- **Local:** put it in `.env` as `LINKEDIN_ACCESS_TOKEN=...`
- **CI:** add it as a GitHub Actions Secret (below)

### Token lifetime & revocation

- Member access tokens expire after ~60 days. When LinkedIn starts returning
  `401 Unauthorized`, regenerate with `npm run auth`.
- To revoke access immediately: delete/reset the developer app in
  [LinkedIn developer settings](https://www.linkedin.com/developers/apps).
- **Never** commit a token, client ID, or client secret.

## GitHub Actions Setup

### Repository secrets

1. Open your repository → **Settings** → **Secrets and variables** → **Actions**.
2. Click **New repository secret** and add:

| Secret | Value |
|--------|-------|
| `GEMINI_API_KEY` | Your Gemini API key |
| `LINKEDIN_ACCESS_TOKEN` | Your LinkedIn access token |

3. Optionally add private knowledge files as base64 secrets if your repo is
   public (the workflow decodes them to `config/` on the runner):

```bash
# local one-liners to produce the secret values
base64 -w0 config/today_notes.txt   # paste output as secret TODAY_NOTES_B64
base64 -w0 config/syllabus.txt      # → SYLLABUS_B64
base64 -w0 config/rules.txt         # → RULES_B64
base64 -w0 config/identity.txt      # → IDENTITY_B64
base64 -w0 config/settings.json     # → SETTINGS_B64
```

> If your fork is private, you can skip the base64 secrets and commit the
> config files directly.

### Enable the workflow

Push the repository (the workflow file lives in `.github/workflows/`). The
workflow is triggered by the schedule and can also be run manually from the
**Actions** tab.

## Scheduling

The workflow uses **GitHub Actions cron, which is always UTC**:

```yaml
- cron: '0 13 * * 1'   # Monday,    13:00 UTC
- cron: '0 13 * * 3'   # Wednesday, 13:00 UTC
```

To convert your local time to UTC, use any timezone converter. Examples:

| Local time | Timezone | UTC cron |
|------------|----------|----------|
| 18:00 Monday & Wednesday | Pakistan (PKT, UTC+5) | `0 13 * * 1` / `0 13 * * 3` |
| 09:00 Monday & Wednesday | New York (EDT, UTC-4) | `0 13 * * 1` / `0 13 * * 3` |
| 14:00 Tuesday only | Berlin (CEST, UTC+2) | `0 12 * * 2` |

Cron format: `minute hour day-of-month month day-of-week` — days 0–6 = Sun–Sat.

Keep `POST_TIMEZONE`/`config/settings.json` in sync with your cron so the
day-of-week check matches (the script only posts on the configured days).

## Customizing Topics

Edit `config/settings.json` (or use env vars):

```json
{
  "timezone": "UTC",
  "scheduleDays": ["monday", "wednesday"],
  "topics": {
    "monday": "Machine Learning",
    "wednesday": "Rust"
  }
}
```

Change `scheduleDays` and the workflow cron together when you want different
days.

## Customizing Writing Style

1. **`config/rules.txt`** — your style rules (tone, banned words, formatting).
   These are injected into every prompt.
2. **`config/identity.txt`** — who the posts are written as.
3. **`config/settings.json`** — limits: word counts, emoji/hashtag caps,
   rewrite attempts, similarity threshold.
4. **`scripts/generate-post.js`** — the prompt template and random style
   pickers (length tiers, openings, layouts, tones). The prompt uses honest
   language like "varied post generation" — it is not claimed to be
   undetectable AI writing.

## Troubleshooting

| Problem | Likely cause / fix |
|---------|--------------------|
| `GEMINI_API_KEY is required` | Key missing in `.env` / secret. Add it. |
| `LINKEDIN_ACCESS_TOKEN is required` | Token missing. Run `npm run auth`, store it. |
| `API key not valid` (Gemini) | Wrong or expired Gemini key. Rotate it. |
| `401 Unauthorized` (LinkedIn) | Token expired (~60 days) or revoked. Re-run `npm run auth`. |
| Publish fails with a 403 / product error | Your app lacks the **Share on LinkedIn** product approval. |
| Workflow runs but nothing posts | Check the run log: "Today is not a schedule day" means cron/settings mismatch. |
| `Too similar to previous post` | The post repeats archived content — the validator rejected it (by design). |
| Post rejected after 3 rewrites | Quality checks keep failing; inspect `archive/*rejected*` and adjust rules. |

## Security

See [SECURITY.md](SECURITY.md). In short:

- **Never commit** `.env`, tokens, API keys, client secrets, MCP credentials,
  or your private `config/` files and archives.
- Use GitHub **Secrets**, never values in the workflow file.
- If a secret is committed, **rotate it immediately** — deleting the file is
  not enough, because Git history keeps it. For a project like this, the
  cleanest fix is to create a fresh repository with no history.
- GitHub secret scanning may flag leaked credentials; treat notifications
  seriously.

## Architecture

| Path | Purpose |
|------|---------|
| `.github/workflows/linkedin-post.yml` | Cron schedule, secrets, CI steps |
| `scripts/post-automation.js` | Orchestrator (scheduled / dry-run / test-publish) |
| `scripts/config.js` | Env + settings loading (no hardcoded paths) |
| `scripts/knowledge.js` | Knowledge-source readers (notes, syllabus, archive, rules) |
| `scripts/generate-post.js` | Gemini prompt builder + API call |
| `scripts/validate-post.js` | Self-review validator (pure functions) |
| `scripts/linkedin.js` | LinkedIn UGC API publishing |
| `scripts/linkedin-auth.js` | OAuth 2.0 token helper (`npm run auth`) |
| `config/*.example.*` | Public templates — copy to real files locally |
| `archive/` | Published posts / drafts (gitignored) |
| `tests/` | Validator unit tests (`npm test`) |
